**信息不重复**（同一数值只会出现在一处）：

- 心率 / 血氧 / 呼吸 只出现在波形区通道块里 —— 标题栏不再重复这三个数字，
  生命体征列表也会跳过这三项（关掉波形时它们会自动回到列表，不会丢数据）。
- 状态条只写状态本身（「状态良好 / 状态欠佳 / 状态异常 / 危急状态 / 垂危状态 / 濒死状态 / 角色已死亡」），
  不再列举指标名——指标在下方卡片中本来就有。
- 标题栏右上角是 **✕ 关闭按钮**（悬停变红），不再显示「正常 / 注意 / 危急」等文字；
  整体档位改由左侧状态灯 + 顶部色线 + 状态条三处颜色表达。

设计原则：

- **圆角 + 分层表面（现代系统设计）**：外框 18px 圆角、卡片 12px 圆角，每层表面都有 **1px 描边**；
  标题栏是面板内的一张独立圆角表面（而不是通栏色带），所有元素都在圆角之内，不会出现直角外露。
- **分级配色**：数值正常时保持中性白，只有异常才染色（青=注意 / 琥珀=警告 / 红=危急），
  危急卡片带左侧色条与淡红底 —— 平静时安静，危急时刺眼。
- **状态条三态**：正常绿色常亮；非致命问题黄色闪烁；致命（含濒死/死亡）红色闪烁。
  闪烁可在设置里关掉（`AlertFlash`），关掉后为常亮同色。
- **告警驱动**：次要指标（心颤、败血性休克、辐射病、血胸、内出血、中风…）**默认只在异常时出现**，
  正常时整屏清爽；可在设置里切换为「始终显示」。
- **全部自绘**：图标、圆角、描边、胶囊、网格纸、辉光、关闭按钮的 ✕、圆形头像遮罩
  都是运行时程序化生成，不依赖字体与美术资源，改动主题色即可整体换肤。

### 队友头像与详情

- 头像与 SteamID 来自联机 MOD（KrokoshaCasualtiesMP 已把 Steam 头像加载好挂在 `NetPlayer` 上），
  插件通过**纯反射**读取：候选属性 `profilepic_any_largetosmall`，并回退到三个 `profilepic_*icon` 字段。
- 插件会把方形头像转成**圆形**（抗锯齿圆边 + 1px 轮廓 + 双线性缩放）并缓存；
  头像本身是懒加载的，暂时拿不到时限时退避重试（3 秒），
  **始终拿不到就只显示名字**（文字自动左移占满，不留空洞）。
- 未安装联机 MOD 时没有队友，也就不会有头像——不会因为缺少 Steamworks 而报错。

- **点击队友卡片**会打开该队友的详情窗口（模态）：顶部是头像 / 名字 / 距离 + 当前状态条，
  下面是**与本人页面完全相同的全部指标** —— 四个生理分组的全部体征（含疼痛、感染、
  心情、免疫、技能等级等）+ 逐条肢体的皮肤/肌肉/疼痛/出血/弹片/骨折状态。可滚轮滚动。
  关闭方式：右上角 ✕、点击窗口外、或按 Esc。

### 组件卡（浮动状态卡）

**不占用任何游戏按键**。在设置页点「打开组件卡摆放界面」进入摆放模式：屏幕变成画布
（方格 + 屏幕边界），主面板暂时让位，两侧是**抽屉式侧栏**——平时收在屏幕边只露一条把手，
**鼠标靠近屏幕边缘自动展开，离开自动收起**；把手本身是一个**可点击的按钮**
（`▶`/`◀` 指示方向、`●` 表示已固定），点一下即可**固定展开**，再点恢复成"跟随鼠标"。

| 位置 | 作用 |
|------|------|
| **右栏 · 组件库** | 生命体征 / 肢体 / 队友三组，每一项**直接渲染组件卡真实的样子**（等比预览，不是文字列表）。拖到屏幕上即在该处生成；直接点击则放到画布中央 |
| **左栏 · 属性** | 选中组件卡的**不透明度**、**卡片大小**、**按方格摆放**开关、位置，以及删除 / 清空全部 |
| **键盘** | `Delete` / `退格` 删除选中的组件卡；`Esc` 保存并关闭摆放界面，**且不会影响游戏状态**（不会弹出暂停菜单。想放弃改动请点左栏「取消」） |
| **栏底** | **保存** / **取消** |
| 画布 | 拖动组件卡移动位置：未开方格时靠近屏幕边缘 18px 自动吸附；开启「按方格摆放」后位置**严格遵守网格**（**新生成的卡片默认开启**）。网格密度在左栏「画布」里调节。选中/拖出一张后组件库会自动收起 |

- **未点保存前不会写配置**，所以「取消」是完全回滚（含透明度、大小、网格等所有改动）。
- **摆放期间会阻断游戏输入**：点卡片、拖滑块都不会误触发游戏操作（开火 / 移动 / 开背包 / 交互）。
  做法是用游戏自己的暂停标志让它的输入处理整体短路，同时**不弹出暂停菜单**；
  退出摆放界面立即还原（包括"本来就是暂停状态打开的"这种情况）。
- **每张组件卡有自己的不透明度（25%–100%）和大小（60%–180%）**，互不影响；卡片内容随大小一起等比缩放。
- **按方格摆放**：新生成的组件卡**默认开启**；开启后卡片位置严格吸附到画布网格
  （与屏幕上显示的方格同一套格线），不再做边缘吸附——适合把多张卡对齐成整齐的一列/一排。
  **网格密度可在摆放界面左栏「画布」里调节**（8–96 像素，越小越密），配置键 `FloatCards/GridSize`。
- 组件卡**显示与否**由快捷键（`Keys/FloatToggle`，默认 **F2**）或设置页的「显示组件卡」开关控制，
  与摆放界面互相独立——摆好之后随时可以一键收起。
- **只在游戏中显示**：存档加载完成（能读到本地玩家）后才出现；打开**暂停菜单时随游戏的暂停动画淡出**，
  回到游戏自动淡入——不会浮在暂停菜单上面。
- 不处于摆放模式时组件卡**只显示、不响应鼠标**，不会干扰游戏操作。
- 组件卡内容与主面板**共用同一套卡片渲染**，因此是实时数据、样式完全一致；
  数据源暂时不存在时（如队友离开）显示「暂无数据」占位，而不是消失。
- **面板与组件卡都被限制在屏幕内**：拖动与拖拽落点都会先夹进屏幕（网格对齐后也会再夹一次）；
  换分辨率后旧的越界坐标也会自动夹回。
- 上限 12 张；配置键 `FloatCards/Cards`（`kind|key|x|y|opacity|scale|gridSnap`，多条用 `;` 分隔，
  旧版 5 字段格式仍可读）。

## ✨ 功能特性

- ✅ **生命体征页**：循环 / 神经感知 / 代谢 / 体能 四个系统，30+ 项指标
- ✅ **肢体页**：每条肢体显示**皮肤/肌肉健康（分条）+ 疼痛 + 感染 + 出血量 + 弹片 + 骨折/脱臼/断肢/止血状态胶囊**，按严重度排序、要害优先
- ✅ **队友简表**：Steam 圆形头像 + 名字、距离、分级徽章、心率/血氧/意识、状态摘要 + 血量条；**拿不到头像时只显示名字**
- ✅ **队友详情**：**点击队友卡片**打开模态详情，指标项与本人页面**完全一致**（全部体征 + 逐条肢体），可滚动
- ✅ **危急警示**：状态条三态（绿常亮 / 黄闪 / 红闪）+ 状态灯 + 顶部色线 + 卡片染色
- ✅ **ECG 打开即铺满**：一次性回填整屏历史波形（一屏约 6 个连续心跳），不会再出现「一条线慢慢长、其余大片空白」；血氧用浓度条、呼吸单条波形
- ✅ **组件卡（浮动状态卡）**：设置页进入**摆放界面**——两侧抽屉面板鼠标靠近自动展开，组件库**显示卡片真实的样子**，拖到屏幕上摆放；左栏调**不透明度 / 大小 / 按方格摆放**，保存或取消；显示由**自定义快捷键**（默认 F2）一键开关
- ✅ **统计选项卡**：累计记录挖掘 / 放置方块、道具使用、场景物交互、容器存取、购买、移动与升降高度等，**加密**保存在本地（`CUStatsHud.stats.dat`），不联网
- ✅ **界面风格可切换**：`CU-UI`（小狐狸 UI，深蓝黑 + 蓝紫强调色）/ `游戏风格`（灰阶冷调 + 青绿强调色）；
  **圆角保持一致**，只有配色不同；分级色（红黄绿）与波形通道色是功能色，两套风格下含义一致
- ✅ **emoji 可关闭**：关掉后界面**不再显示任何装饰图标**（文字自动左移填补空位）；关闭按钮的 ✕ 等功能图标不受影响
- ✅ **完全可配置**：自定义快捷键（面板内点击后直接按键绑定）、面板位置/尺寸/缩放记忆、透明度、字号、字体来源、各类开关
- ✅ **emoji 小图标**：39 个语义化图标随 DLL 内嵌分发，无需额外文件；设置页只放可操作项，所有说明集中在「关于」窗口
- ✅ **配置向后兼容**：沿用 v1.2 的配置键名，旧配置文件无需改动
- ✅ **单机 / 联机双模**：联机走 KrokoshaCasualtiesMP 反射，未装 MOD 时自动退化为场景扫描，插件不会因缺 MOD 而失效

## 📦 安装

1. 确认已安装 **BepInEx 5.4.x**。
2. 把编译好的 `CUStatsHud.dll` 放进 `Casualties Unknown Demo\BepInEx\plugins\`。
3. 启动游戏，按 **F1** 显示/隐藏面板（可在设置页改键）。

### 环境要求

| 依赖 | 版本 | 说明 |
|------|------|------|
| Casualties Unknown | Demo（Unity 2022.3.62f3 / Mono） | 游戏本体 |

| Windows | >= 10 | 操作系统 |
| KrokoshaCasualtiesMP | 可选 | 装了才有联机队友列表；不装也能用 |

## 🔨 从源码编译

工程已改为标准 SDK 风格 `.csproj`，直接用 dotnet 编译，**不需要手写 csc 命令**：

```bash
# 默认从 Steam 默认安装路径读取游戏程序集
dotnet build -c Release

# 游戏装在别处时用 GameDir 覆盖
dotnet build -c Release -p:GameDir="D:\Steam\steamapps\common\Casualties Unknown Demo"
```

产物：`bin\CUStatsHud.dll`

工程只引用游戏目录里的程序集（`CasualtiesUnknown_Data\Managed\*.dll` 与 `BepInEx\core\BepInEx.dll`），
**不会把游戏 DLL 复制进仓库**；目标框架 `net48`，与游戏自带 Mono 运行时一致。
联机 MOD 仅通过反射访问，因此工程不引用 `KrokoshaCasualtiesMP.dll`。

```
  AvatarCache.cs             Steam 圆形头像的生成与缓存（拿不到就不画）

  HudStyles.cs               全部 GUIStyle 与底纹，缩放变化时整体重建
  Waveform.cs                波形纸带组件（ECG 回填 + 呼吸波）
  Widgets.cs                 自绘控件：卡片 / 数值行 / 条形 / 徽章 / 状态条 / 关闭按钮 / 滚动
  HudState.cs                界面运行状态（窗口几何、滚动、动画、资源生命周期）
  FloatingCardHost.cs        浮动组件卡宿主（摆放会话、拖动、吸附、独立透明度）
  Panels/
    MonitorWindow.cs         主窗口框架：标题栏 / 状态条 / 波形区 / 标签栏 / 内容区 / 底栏
    CardLayoutEditor.cs      组件卡摆放界面（右侧组件库拖入 + 左侧属性 + 保存/取消）
    VitalsPanel.cs           生命体征页
    LimbsPanel.cs            肢体页
    TeamPanel.cs             队友页（卡片列表 + 点击进入详情）
    MateDetailDialog.cs      队友详情窗口（复用体征/肢体面板，信息项与本人一致）
    SettingsPanel.cs         设置页（只有可操作项，不含说明文字）
    AboutDialog.cs           关于窗口（作者卡片 + 快速上手 / 功能说明 / 数据说明 / 图标许可，可滚动）
```

分层约定：`Core` 只负责「读数据 + 判分级 + 格式化」，`UI` 只负责「画」，
`VitalRules` 完全不依赖 UnityEngine，因此可以用一个普通控制台工程直接跑断言测试。

实现要点：

- **随 DLL 内嵌**：图片以 `EmbeddedResource` 打进程序集（逻辑名 `CUStatsHud.emoji.<码点>`），
  运行期用 `Texture2D.LoadImage` 读取，所以插件仍是**单文件分发**，
  不需要额外的图片目录，也不会被游戏资源卸载影响。DLL 体积约 +70 KB。
- **暗色图标亮度补偿**：面板底色接近纯黑，像 🩺 深灰听诊器这种图标会看不清。
  载入时按「**暗 且 低饱和**」判据抬亮（`rgb' = rgb + (1-rgb)*k`）；
  饱和的深红图标（🩸 血滴、🫀 心脏）不处理——它们在深色背景上对比度本来就够，
  抬亮反而会变粉、丢掉辨识度。
- **图标与分级解耦**：emoji 是彩色的，无法再着色，因此分级由卡片底色、左侧色条与数值颜色表达；
  图标只用透明度区分状态（危急/警告全亮，正常略降）。缺失 emoji 时自动回退到程序化几何图标。
- **映射集中管理**：种类 → 码点的对应表在 `UI/IconProvider.cs`，
  `Core/BodyReader.cs` 只填语义化种类名（`blood` / `oxygen` / `thermo` …）。
- **授权**：图形来自 [Twemoji](https://github.com/jdecked/twemoji)，**CC-BY 4.0**，
  详见 [emoji/README.md](emoji/README.md)；「关于」窗口内已标注该署名。

## 🚨 告警阈值来源

监护仪的红线不是拍脑袋定的，全部对齐游戏 `Assembly-CSharp` 里 `Body` 自身的判定，
因此**面板变红 ≈ 游戏认为你快死了**。主要映射：

| 指标 | 分级红线 | 游戏内出处 |
|------|----------|------------|
| 心率 | 危急 `< 20`（心脏骤停）/ `> 200`（室颤倾向） | `Body.inCardiacArrest`、`Body.fibrillationRising` |
| 血压 | 危急 `< 70`；警告 `< 80` 或 `> 170` | `Body.isCriticallyDying`、`Body.isDying` |
| 血氧 | 危急 `< 50`；警告 `< 65` | 同上 |
| 剩余血量 | 危急 `< 30` 且出血；警告 `< 40` 且出血 | 同上（游戏要求同时满足出血条件） |
| 流血速率 | 危急 `> 0.134`；警告 `> 0.02` | 同上 |
| 体温 | 危急 `< 27` 或 `> 41.5`；警告 `< 29` 或 `> 41` | 同上 |
| 意识 | 昏迷 `< 30`；危急 `< 5` | `Body.conscious`、`Body.brainDying` |
| 疼痛 | 注意 `> 25`；警告 `> 50` | 游戏在 `averagePain > 50` 且清醒时触发呼喊；疼痛**最高只到警告**，不会单独把面板打成「危急」（游戏 `isCriticallyDying` 不依赖疼痛） |
| 心情 | 危急 `< -75`；警告 `< -20` | `Body.aboveMedicalCutoff`、`Body.allowUseItem` |
| 饥饿 / 口渴 | 危急 `≤ 0` / `> 175`；警告 `< 10` | `Body.isCriticallyDying`、`Body.isDying` |
| 败血性休克 | 警告 `> 75`；危急 `> 82.5` | `Body.isDying`、`Body.isCriticallyDying` |
| 辐射病 / 中风 | 危急 `> 60` / `> 50` | `Body.isDying` |
| 心颤 | 危急 `> 60`；上升期 `> 1` 即警告 | `Body.isCriticallyDying`（另：`> 75` 时游戏开始压制 ECG 波形幅度） |
| 精力 | 注意 `< 35`（游戏认为该睡了） | `Body.canTakeNap` |
| 免疫 | 警告 `< 40`；注意 `< 90` | `Body.Update` 中钳制在 0-200，基准 100 |

游戏未给出明确阈值的少数指标（疼痛性休克、组织损伤、潮湿等）在代码注释里标注为「经验值」，
并在 `Core/VitalRules.cs` 中集中定义，便于按需调整。

## 🔤 字体说明

游戏的文字实际由 TextMeshPro 渲染，而插件能拿到的 TrueType `Font` 对象往往**字形不全**。
IMGUI 遇到缺字会逐字回退到另一个字体，于是同一行里有的字母明显更粗、字形也不对。

因此 `FontMode` 有自动回退机制：

- `auto`（默认）：优先系统字体（微软雅黑 → Noto/思源 → 黑体），中英文覆盖最完整、字重统一；
- `system`：只用系统字体；
- `game`：优先游戏自带字体，但会先用**字形覆盖率探测**（ASCII 全量 + 面板用到的中文）
  挑出最完整的一个；覆盖率不足 90% 就直接回退系统字体，宁可用一个完整字体，
  也不要一行里混着三四种字重。

设置页会显示**当前实际生效的字体名**，便于确认到底用了哪个。

## 🔬 数据真实性说明

- **ECG 来自游戏真实心电曲线**（`Body.GetECGHeight`，与游戏自带 `ECGVisualizer` 同一数据源），
  心率、房颤程度会真实改变波形。
- **打开即铺满整屏（回填历史）**：纸带建立时不会从空白开始一列列长，而是**一次性把整屏写满**——
  用 `EcgTimeline` 把每一列对应的时间点折进 `GetECGHeight` 的有效相位窗口，
  采样出过去约 4.6 秒的**真实曲线**（曲线本身以 1 个心动周期为周期，整数周期平移不改变形状）。
  所以面板一打开就是连续好几个心跳，不需要等它慢慢画满。
- **扫速与基线**：每列 0.010 秒，约 4.6 秒滚动一屏（一屏 5~8 个心跳，与真机一致）；
  纸带中间有一条**常驻等电位基线**（不参与余辉衰减），回填之后未滚动到的区域也不会是空洞。
- **血氧用浓度条而不是波形**：血氧是「浓度」，波形看不出高低。
  浓度条填充长度 = 血氧饱和度，90% 处有危险阈值刻度，阈值以下区域带淡红底，
  低于阈值时填充色自动转为琥珀 / 红 —— 一眼就能看出"还剩多少"。
- **RESP 呼吸波是示意波形**：游戏没有对外暴露呼吸曲线，波形形状由呼吸频率推算，
  旁边的数值标签（呼吸 /m）是真实读数。
- **距离**：队友卡片显示的距离是本地玩家与该玩家的世界坐标直线距离，按 1 Unity 单位 ≈ 1 米呈现。
- **单机兜底**：未加载联机 MOD 时，队友页退化为列出场景内其它存活 `Body`，
  无法区分 NPC，因此名字会标注为「观察对象 N（对象名）」。
- 血氧、意识、大脑完整度、饥饿等本就是 0-100 的百分比，面板直接按百分比显示，
  不再使用旧版「小于 1.5 就当分数」的猜测式换算。

## 📈 统计选项卡

面板第 5 个标签页，记录玩家的游戏行为。**全部为累计值**（不分会话），
**本地采集、加密保存、不联网**，首次运行时在 `BepInEx/config/CUStatsHud.stats.dat` 生成数据文件。

### 数据来源（每项都在反编译源码里核对过）

| 统计项 | 采集方式 |
|---|---|
| 挖掘方块 | `WorldGeneration.SetBlock(pos, block)`，`block == 0` 为挖掉 |
| 放置方块 | 同上，`block > 0` 为放置（玩家放置走 `Item` 的 `useAction`） |
| 道具使用 | `Body.UseItem` / `Body.UseItemInHand`（只统计本地玩家）；**空手挥击直接丢弃、不计数**，见下方说明 |
| **道具明细** | 按 `Item.id` 分类，统计每种道具用了多少次 |
| **制作明细** | `Recipe.TryMake()`，按配方名（`fullName`）分类 |
| **技能 / 经验** | `Body.skills`：STR / RES / INT 等级、累计获得经验、升级次数 |
| 场景物交互 | 全游戏实现 `OnUse()` 的 10 个类：电池充电器、生物终端、钻探舱、救生舱按钮、可开启物、碎料机、幸存者笔记、终端、商人、教学制作按钮 |
| 容器存取 | `Container.LoadItem` / `Container.UnloadItem` |
| 商品购买 | `TraderScript.TryPurchase` |
| 移动 / 行走距离 | 本地玩家每帧位移累加（行走只算水平分量） |
| 下降 / 上升高度 | 同上，按 Y 分量正负分别累加 |
| 最长单次下落 | 连续下降段的峰值 |
| 最大 / 平均速度 | 单帧位移 / 帧时长；平均 = 累计距离 / 累计时长 |
| 启动次数、游玩时长、首次/最近使用 | 插件加载时记录 |

**只统计玩家附近的方块 / 交互**：`SetBlock` 也是世界生成与爆炸的入口，
所以加了 20 方块半径判断（玩家挖掘/放置都在 5 单位内）；场景交互加 60 单位判断，
避免 NPC 自己用容器之类被算进来。

**传送不算位移**：单帧位移超过 40 单位判定为传送/切场景，只重设位置锚点。

**经验怎么算的**：`Skills.expSTR/expRES/expINT` 是**累计经验**而不是当前级内进度
（`Setup` 把它们初始化成 `GetExperienceForLevel(等级)`，之后 `AddExp` 直接累加），
所以三者之和就是总经验，减去**首次观测的基线**得到「累计获得」——
这样换存档时基线会重建，不会把新角色的初始经验算成你获得的。

**分类明细的容量**：明细最多记录 200 种（防止异常情况无限膨胀），超出的种类只累计总数。
道具显示的是游戏内部 id（如 `bandage`、`climbingrope`），因为游戏没有提供本地化的物品名表。

**空手挥击不计入道具使用，也不单独统计**：游戏在没有可用物品时会把「使用」动作变成一次空手挥击，
那次调用同样会走到 `UseItemInHand`，但它并没有动用任何道具。
旧版把这类调用一并计进「道具使用」，导致**总数与分类明细之和永远对不上**；
现在这类调用**直接丢弃**，既不进总数、也不进明细，也不再单列成一栏。

判定依据（已对游戏程序集实测核对）：`Body` 上并没有直接持有物品的字段——
`int handSlot` 只是**槽位索引**，`InventorySlot[] slots` 是槽位数组。
游戏自己的读取入口是 `Item Body.GetItem(int slot)`，所以「手上有东西吗」等价于
`GetItem(handSlot) != null`。

判定顺序（`Core/ItemUseProbe.cs` + `Patch/GameStatsHooks.NoteItemUseInHand`）分三级：

1. **前后指纹比对优先**。插件每帧缓存一份「物品状况指纹」（手持槽物品的实例 ID，读不到就退到 `slots` 的元素序列），
   `UseItemInHand` 执行后再取一份——**指纹变了**说明物品真的被消耗/替换，计为真实使用；
   **没变**说明什么都没动，判为空手挥击并丢弃。这一级不依赖具体字段名。
2. **退回读手持槽**。指纹比对不可用时，用 `GetItem(handSlot)` 判断：非 null 判为真实使用，
   null 判为空挥（此处无法区分「本来就空手」与「刚用掉最后一个」，按更常见的情形处理）。
3. **两级都不可用**则保守放行（记一次使用、归到「（未分类）」），
   并在 BepInEx 日志里提示一次，宁可偏多也不永久丢光统计。

配套的两处细节：

- **后置补丁不能只看最终状态**。「用掉最后一个绷带」的调用结束时手持槽本来就是空的，
  若直接采信「空」就会丢掉最该记的那一次——所以指纹比对排在读手持槽**之前**。
- **同动作去重**：`UseItem`（带具体 `Item`）与 `UseItemInHand` 可能是同一次动作的两个阶段，
  两者都在 0.25 秒窗口内触发时只记一次。

因此「道具使用」恒等于分类明细之和
（`UseItemInHand` 拿不到被消耗物品的 id，这部分统一归到「（未分类）」）。

> 旧存档会自动清理：老数据里 `itemsUsed − 明细之和` 的差额就是当年无法区分的空挥，
> 加载时把 `itemsUsed` 收敛到明细之和（把那部分空挥去掉），道具明细原样保留，清理只做一次。

### 没做的项（以及原因）

- **攻击次数**：`Body.Attack` 的签名在反编译源码里没能定位到，不做未经验证的 hook。

### 文件加密

AES-256-CBC + PKCS7，密钥由插件标识与固定盐经 PBKDF2(SHA256, 50000 次) 派生，
文件内容为 `CUSH1:` 前缀 + Base64，**纯文本可读性已消除**。

> ⚠️ 如实说明：密钥随插件一起分发，所以这是「防玩家随手查看/直接改存档」的级别，
> 不是强安全边界——能反编译插件的人依然能解出来。对本地统计这个量级的需求这是合适的取舍。
> 数据损坏或被改坏时解密失败，插件会记一条警告并重新开始统计，不会影响游玩。

## ⚠️ 已知限制

- 面板是 IMGUI 覆盖层：**鼠标点击会同时传给游戏**。建议把面板放在不影响操作的角落，
  或只在需要时按快捷键呼出（这也是默认行为）。
- 同理，在设置页绑定快捷键时，那一次按键也会被游戏收到（例如把快捷键绑成游戏里已有的按键，
  会同时触发游戏内动作）。绑定后不影响后续使用。
- 未做多语言：界面文案为中文，`Core`/`UI` 里的字符串集中在各面板文件中，便于后续抽取。
- 未做游戏内「按住按键才显示」模式。
- ECG 与 RESP 波形是「滚动纸带 + 余辉」风格（与游戏自带 `ECGVisualizer` 一致），每列约 0.028 秒，
  拖尾约 410 列；RESP 波形为依据呼吸频率推算的示意曲线，只有 ECG 是游戏真实曲线。
